# 本地战斗测试模式

## 状态

- 文档状态：已确认，并作为本地战斗测试模式的权威口径。
- 实现状态：不得依据旧线程回复或历史截图判定；须按当前代码、测试结果和真实浏览器行为重新审计。
- 最近状态：典狱长后续开发任务已被用户中断，未验收项不得自动续做或写成通过。
- 确认日期：2026-07-14
- 目的：为本地开发和浏览器验收提供一个可重复的第一关战斗测试入口。
- 本模式不是正式玩法、不是关卡入口、不是存档功能，也不进入生产构建。

## 第一性边界

1. Web 项目仍是唯一正式运行时；本模式只服务本地开发测试。
2. 本模式必须复用第一关正式战斗的地图、障碍物、装饰物、碰撞范围、素材和战斗渲染路径，不得复制一套测试地图或绘制一套测试障碍。
3. 本模式不得改变普通关卡的怪物配置、刷新、奖励、结算、存档、装备、金币、天赋点或通关记录。
4. 本模式中的怪物选择只改变当前测试会话的生成集合，不改变正式关卡配置。
5. 未登记、缺少有效素材或缺少完整战斗数据的实体不得被测试入口生成。
6. 任何本地入口必须同时有 UI 层和运行时动作层的开发环境保护；隐藏按钮不能作为唯一安全措施。

## 首页入口

- 首页右上角现有 `测试` 入口下方新增 `战斗` 按钮。
- `战斗` 仅在 Vite 开发环境（`import.meta.env.DEV`）显示。
- 生产构建和部署页面不渲染该按钮，也不能通过普通 UI 动作进入测试模式。
- 点击 `战斗` 后直接创建一次独立的第一关战斗测试会话，不打开正常传送门选择和正式关卡流程。
- 不新增地图、难度或奖励选择；地图固定为第一关死契地牢，难度固定使用当前第一关地图与障碍物配置。

## 测试会话

### 初始状态

- 复用当前角色、装备、主动技能和局外/局内构筑状态，保证可以验证真实战斗组合。
- 玩家出生在第一关的合法安全出生点。
- 地图、障碍物和装饰物由正式第一关初始化链路生成。
- 测试会话使用独立的内存状态，不写入正常存档。

### 流程隔离

测试会话内禁止以下正式流程：

- 自动关卡推进和正常层间结算
- 天赋点、金币、材料、装备和经验收益
- 紫色及以上装备保留或失败结算
- 通关记录、首通记录、最高层记录和 Boss 击杀记录
- 正式奖励池、掉落池和经济统计写入

页面上应明确显示测试状态。退出测试后返回首页，不把测试结果合并到正常对局。

### 正常控制保留

- 角色移动、普攻、主动技能、碰撞、伤害、受击、死亡和素材播放沿用正式战斗逻辑。
- 怪物生成后必须复用正式关卡的怪物定义、create / spawn 管线、AI、技能、碰撞、伤害和受击处理；本模式只改变选择、数量和生成入口，不提供测试专用数值、技能、AI、碰撞、动作或掉落分支。
- ESC 暂停行为沿用正式战斗逻辑。
- 资产测试面板和战斗测试面板可以共存，但打开面板时必须暂停战斗 tick，避免面板操作期间继续产生战斗结果。

## 怪物测试控制

- 测试会话右上角新增本地专用 `怪物` 按钮。
- 点击后暂停战斗并打开怪物选择面板；关闭面板后恢复战斗。
- 怪物按普通、精英、Boss 分组，数据来源必须是当前运行时已登记的怪物实体清单。
- 每种怪物支持启用/禁用和生成数量设置；数量必须有上限，初版建议单类 1-20 只，并受同屏性能上限约束。
- 初版采用手动生成：关闭正式自动刷怪和波次补充，只生成开发者明确选择的怪物。
- 点击 `应用配置` 时清除当前测试会话内的敌人，再按选择的类型和数量生成，保证结果可重复。
- 生成必须使用现有合法出生点搜索和碰撞检测，禁止生成在玩家、障碍物、装饰物阻挡区域或不可达位置。
- 面板提供 `清空怪物` 和 `应用配置` 两个动作；没有选择怪物时只能清空，不能伪造默认敌人。
- 选择配置只存在于当前测试会话内，不写 localStorage，不写项目配置，不改变正式怪物池。

## 怪物范围

- 初版开放当前代码中同时具备稳定 ID、属性、行为、攻击/技能消费和项目内可用动作素材的实体；可用性依据真实登记、资源和 create / spawn 管线判断，不以 C/D 独立验收通过作为生成门禁。
- 具备项目内可用动作素材和真实生成管线的 Boss（包括 `dungeon-warden`）可以在开发环境本地测试中选择和生成。该操作只创建测试会话实体，不代表正式战役解锁、Boss 验收通过或正式关卡可用。
- 骷髅战士 `dungeon-skeleton-warrior` 的本地测试必须复用正式第一关的素材 manifest、动作状态机和防御技能；本地入口不得为防御技能增加强制触发、无敌或测试专用减伤分支。
- 实际项目资源缺失、动作不可用、实体未登记或真实生成管线无法创建时，实体必须显示为禁用并给出准确原因；不得使用占位图、自绘素材、测试专用数据或绕过正式 create / spawn 管线强行生成。

## 退出与异常

- `退出测试` 返回首页，并丢弃整个测试会话内存状态。
- 页面刷新、浏览器关闭或运行时异常不得把测试收益写入正常存档。
- 如果本模式初始化失败，应显示明确错误并返回首页，不得静默降级成正式第一关或旧地图。

## 实现边界与职责

- A「程序员(战斗内核)」：测试会话状态、第一关初始化复用、手动怪物生成、自动刷怪隔离、碰撞/出生点校验、无结算隔离。
- B「程序员(UI/数据结构/配置)」：首页 `战斗` 入口、测试会话 HUD、右上角 `怪物` 面板、类型/数量配置、开发环境显示保护和组件测试。
- C「验收(战斗/浏览器)」：本地入口、第一关地图和障碍物一致性、生成位置、战斗行为、暂停/退出、生产构建隐藏和无自动刷怪验收。
- D「验收(UI/数据/资产)」：面板布局、空选择/数量上限/错误状态、当前素材与实体清单一致性、测试会话不污染存档和正式配置验收。

任何线程开始任务前，必须重新阅读本文档及统筹线程已确认的相关设计，并在回复中明确：

1. 自己负责的范围；
2. 不会越界修改的范围；
3. 将如何证明不污染正式流程；
4. 依赖的测试和浏览器证据。

## 验收最低清单

1. `npm run dev` 首页显示 `战斗`，生产构建和部署页面不显示。
2. 进入后地图、障碍物、装饰物与第一关正式初始化结果一致。
3. 只生成选中的怪物，未选怪物不会出现。
4. 生成物不进入障碍物、装饰物或玩家位置。
5. 打开怪物面板时战斗暂停，关闭后恢复。
6. 清空和重新应用配置可重复得到预期怪物集合。

骷髅战士专项实测还必须能够在本地会话中观察站姿普通攻击、移动、受击、死亡和防御触发；防御需分别验证玩家弹道从正面命中时实际只造成 30% 伤害、从背面命中时造成 100% 伤害，并验证 3 秒持续和 5 秒冷却。若当前入口无法稳定形成上述场景，状态应记录为“工具阻塞”或“已实现但未充分验证”，不得用单元测试或测试桥摘要代替浏览器验收。
7. 退出、刷新、重启后测试数据不进入金币、装备、天赋点、经验和关卡记录。
8. 正常开始游戏、传送门进入关卡和正式结算行为不被改变。
9. 代码测试、构建、格式检查和受保护素材/runtime/dist 检查通过。
