## 4. 分辨率与缩放

- 背景与按钮分别处理尺寸，不把两者固定在一个会留黑边的整体舞台内。背景仅显示一张、禁止重复平铺，等比铺满当前视口，允许裁切边缘，不做非等比拉伸、不留空边；优先保留人物与篝火。本轮不改为完整非等比拉伸，不承诺单图在所有宽高比下既无裁切又无留白；现有单图cover路径继续有效。
- 七按钮保持右侧纵排，边框、金色文字、间距统一按同一个比例缩小或放大。R3用户确认以红框区域替换旧位置和尺寸规则；不再额外乘R2的`2/3`，不沿用旧响应式算法作为第二层缩放。
- 菜单区域只以屏幕为基准：左侧留`78%`视口宽，右侧留`9%`视口宽，上下各留`22%`视口高。因此区域宽`13%`、高`56%`，区域中心在屏幕`84.5%`宽／`50%`高；七项整组居中放入该区域。固定的是区域相对屏幕的比例，不是固定像素或随背景图移动；实际按钮组因等比适配可能在区域内留余量，不承诺组的四边都贴区域边。
- 设计宽480、单框高`480 × 867 / 3000 = 138.72`、间距10、七项整组高1031.04不变。统一比例为`min(viewportWidth × 0.13 / 480, viewportHeight × 0.56 / 1031.04)`，按区域较短约束轴适配；没有旧`min(1, …)`上限或追加2/3。组宽高为设计宽高乘该比例，位置为区域左上角加上各轴剩余空间的一半。背景图片尺寸、比例、焦点与裁切不得参与菜单位置／缩放计算，现有背景焦点30%／82%保持。
- 窄屏／竖屏／低高度同样执行整组等比缩放，**不改为屏幕正中重排、多列网格、折叠菜单或菜单滚动**。此处允许且要求“右侧固定区域内居中”，不是把菜单移至整个屏幕中心。不得由断点分别改变字体、边框和间距比例，也不得把旧建筑热点坐标继续作为菜单位置。
- 不改变按钮原始宽高比、不挤压文字、不裁掉按钮；点击区域与可见按钮保持对应。现有模块弹窗的内部布局不在本次重做范围，保持其可用的响应式行为。
- 极窄屏的文字会随整组变小，这是用户明确选择的布局方式；不得擅自用重排或滚动替代。若实际存在无法满足的尺寸冲突，B2 回报事实与证据，由 Z5 再确认。
