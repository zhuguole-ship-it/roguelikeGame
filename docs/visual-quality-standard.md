# 视觉质量标准

> **2026-08-10 用户确认的视觉风格覆盖**：后续所有视觉设计以 [地牢 UI 美术方向](./dungeon-ui-art-direction.md) 及其中指定的权威锚点为最高优先级。本文档保留分辨率、细节密度、地图主题、战斗边界与验收要求；若与该美术方向的材质、颜色、构图或 UI 语言冲突，以该美术方向为准。

`public/assets/reference/archer-village-dungeon-sheet.png` 继续作为像素插画质量、森林村庄/地穴内容和细节密度参考，但不再是全局艺术方向的最高优先级来源。

## 核心原则

- 不再接受纯矩形占位、低密度平铺草地、单色道路、单层树冠作为最终画面。
- 不使用整张参考图直接作为游戏地图背景。
- 可以截取参考图中的局部元素作为临时资产，但必须重新组合成新的地图。
- 村庄和地穴必须优先表现“森林遗迹弓箭 Roguelite”的题材，而不是通用像素地板。
- 战斗和核心游戏逻辑不因美术升级而改变。
- 普通战斗层后续采用受控伪无限地图，不再依赖固定房间硬边框；地图资产必须支持区块化拼接、随机障碍和主题软边界。

## 分辨率标准

- 游戏逻辑坐标保持 `960 x 640`。
- Canvas 输出像素为 `1920 x 1280`。
- 美术资产应以 `1920 x 1280` 输出效果验收，而不是以 `960 x 640` 占位效果验收。
- 所有地图、建筑、UI 需要在 100% 浏览器截图下保持边缘清晰，不出现非等比拉伸。

## 村庄地图标准

村庄必须是室外森林村庄，不是室内大厅。

必须包含：

- 明确铁匠铺，铁匠在铺子门口打铁。
- 篝火区域，篝火周围有可坐凳子。
- 职业告示牌在地牢传送门旁边。
- 村长或村长小屋。
- 森林边界、树群、草丛、石块、木围栏。
- 有机泥路，不使用整齐方格路作为最终地图主形态。
- 地形高低、阴影或边缘过渡，避免平铺感。

细节密度要求：

- 每个 `96 x 96` 屏幕区域内至少应有 5-8 个可见细节：草簇、花点、石块、阴影、路边破碎边缘、木桩、叶片高光等。
- 道路边缘必须不规则，至少有 2 层颜色过渡。
- 树木至少有 3 层树冠色、树干暗部和地面投影。
- 围栏必须有立柱、横梁、高光和投影，不允许单色长条。
- 建筑必须有屋顶、墙体、门窗、暗部、投影、地基或台阶。
- 篝火必须有光晕、木柴、火焰内外两层颜色和地面投影。

## 地穴地图标准

地穴视觉应靠近参考图中的森林遗迹、洞穴、石桥和水流质感。

必须包含：

- 苔石地面，而不是纯深绿方格。
- 地砖裂缝、苔藓、根须、碎石。
- 墙边、角落、火把或遗迹装饰。
- 障碍物与地面有投影，不能像独立矩形块。

细节密度要求：

- 每个 `64 x 64` 战斗地表区域至少有 3-5 个地面细节。
- 地砖需要至少 4 种变体：普通、苔藓、裂纹、根须。
- 障碍物必须有高光、暗面和落影。

## 无限战斗地图标准

普通战斗层不再用完整房间墙体封边，而是用可循环地面、主题障碍、远景雾化和环境危险表现无限延展。

必须包含：

- 可无缝拼接的地面 tile，区块边缘不能出现明显断层。
- 每个关卡独立的地面污染、障碍物和危险区域边缘。
- 玩家周围清晰可读的可通行空间，不能用装饰物伪装成可穿越道路。
- 契约裂隙资产，用于层目标完成后的结算入口。
- Boss 层专用软边界资产，例如契约雾、血幕、树墙、潮汐墙、火山裂缝。

细节密度要求：

- 每个 `64 x 64` 战斗地表区域至少有 3-5 个地面细节，但不能让蓝晶、敌方预警和玩家技能失去可读性。
- 障碍物必须能从轮廓判断是否可碰撞。
- 危险区域边界必须比普通地面更亮或更饱和，并且先出现预警再造成伤害。
- Boss 软边界不能像空气墙，必须有主题解释和清楚视觉反馈。

## 角色与单位标准

弓箭手参考图是角色质量基准。

- 玩家可读尺寸建议为 `36 x 44` 到 `48 x 56` 显示尺寸。
- 至少有待机、移动、攻击、受击方向感。
- 不能再用纯矩形身体作为最终玩家视觉。
- NPC 至少需要头发/帽子、身体、手部动作、落影。
- 铁匠打铁需要锤子上举/落下和火花。

### 四足怪硬性 QA

四足怪不能只依靠上半身、头部或特效表达。所有四足怪资产在图鉴实际显示尺寸下必须先通过剪影检查。

- 每一组动作至少关键帧必须能读出 4 条腿，或明确读出前腿/后腿的层次和支撑关系。
- `idle`、`move`、`attack`、`skill`、`hit` 不能只有上半身变化，腿部必须参与动作。
- 底部阴影必须和腿、爪分离，不能连成横向深色色块。
- 前腿需要用爪尖、膝关节或边光标出；后腿可以更暗，但仍必须可读。
- `move` 帧必须体现四足步态，不能只是整体平移。
- `attack` 帧前腿需要前探、压低或抓地；吐息类 `skill` 帧前腿需要呈现支撑姿态。
- `death` 帧可以最终塌成余烬或残骸，但前几帧仍要看到腿部倒伏过程。
- 交付前必须自查黑白剪影：如果剪影像一条横向色块，而不是四足动物，则不合格。

## UI 标准

UI 的材料、配色、构图和动效以 `docs/dungeon-ui-art-direction.md` 为准；本节定义的战斗信息可读性与不遮挡地图中心的要求继续有效。

必须包含：

- 深色面板底。
- 金色细边框或角标装饰。
- 头像、红蓝资源条、技能槽必须有像素边框。
- UI 不遮挡主要地图中心。
- 中文文字必须保持清晰，不压住角色或建筑。

## 禁止项

- 禁止把参考图整张 MAP 区域直接铺成村庄背景。
- 禁止继续把大面积地图做成单色 `fillRect`。
- 禁止使用均匀网格感过强的草地/道路作为最终方案。
- 禁止非等比拉伸 Canvas。
- 禁止为了视觉改动战斗、敌人、技能、武器、经济、存档等核心逻辑。

## 验收方式

每次视觉迭代至少检查：

- `npm run build`
- `npm run test`
- `npm run lint`
- 浏览器截图是否与参考图在以下维度接近：
  - 地表细节密度
  - 建筑清晰度
  - 树群层次
  - 道路自然程度
  - 围栏/道具投影
  - UI 边框质感

当前项目如果继续使用程序化 Canvas 绘制，必须把程序化绘制封装成地图/资产层，而不是在主渲染函数里堆叠零散矩形。
