- 图 `3.jpg` 是主要视觉口径：苔藓是石砖下方的潮湿地基，从石砖缺口、断裂边缘、砖群之间的间隙及少量砖缝露出；完整石砖中央区域基本不覆盖苔藓。禁止做成整张石砖上均匀铺一层半透明绿色。

## 2. 分层与稳定性

```text
静态苔藓底层（世界坐标）
  → 不规则石砖覆盖区与边缘遮罩（世界坐标）
    → 现有地面装饰
      → 现有障碍、敌人、玩家、投射物与技能
```

- 石砖与苔藓均须按**世界坐标**而非屏幕坐标绘制；镜头移动、跨区块、离开再返回时，纹理和缺口位置必须保持稳定。
- 基于当前战场 seed 与区块坐标派生稳定的逻辑地形格；以双网格/16 种邻接边缘规则生成石砖连片、外边、内角与缺口边界，避免规则方块和逐格同样重复。
- 实施中的共享纯数据契约固定为：`moss(publicUrl, tileSize)` 与 `stone(tileSize, variantsByMask16)`。其中 `variantsByMask16` 是透明的 16 邻接石砖遮罩；渲染器只消费该配置，不得把素材路径或遮罩规则散落进战斗逻辑。
- 用户提供的石砖与苔藓参考图都必须先做无缝循环检查；若原图边缘会产生明显接缝，先在项目内准备可循环副本，再开始正式接入。不得用每帧随机偏移掩盖接缝。
- 首版苔藓完全静态、纯视觉：不扩散、不随战斗改变，不影响移动、碰撞、寻路、刷怪、投射物遮挡或伤害判定。

## 3. 不变边界

- 不改第一关地形之外的战役主题、村庄、装备、技能、怪物、掉落、存档、战斗数值或地图生成/障碍碰撞规则。
- 第一关第 `1–22` 层保持连续世界与既有 Boss 场域/结算语义；第 `22` 层只能叠加既有 Boss 边界和机制视觉，不得回退到程序化旧地面或另一套底图。
- 石砖/苔藓只替换地面表现层；逻辑障碍仍由现有 `mapObstacles` 和对应碰撞尺寸决定，地面缺口不代表可阻挡、坠落或危险区域。
- 不迁移整套 Canvas 渲染到 WebGL；首版在当前 Canvas 2D 渲染架构中实现，避免借视觉改造重做战斗渲染器。

## 4. 验收标准

- 第一关普通层与第 `22` 层都能消费正式项目内素材；不得读取 Downloads 路径或保留旧 `dungeon-floor-level1-128-image2.png` 的第一关地面消费分支。

- 障碍、玩家、敌人、投射物、技能效果、出生合法性和碰撞行为无回归；地面缺口不得被误作碰撞或危险区域。
