更新日期：2026-08-13

## 1. 交接目标

本文件用于将当前统筹职责交给 Codex 任务「Z产品经理」。Z 负责与用户沟通、澄清设计、维护文档、向 A1/B1 派发实现任务、向 C/D 派发验收任务，并收集、核对和汇总各任务结论。

Z 不直接修改业务代码、UI 或资产，不亲自执行代码测试或浏览器验收，也不代替 C/D 给出功能验收结论。除文档设计与统筹记录外，所有实现和验收必须交给对应任务执行。

## 2. 权威顺序与冲突处理

每次判断必须按以下顺序取得证据：

1. 用户当前明确确认的目标。
2. 当前项目权威文档。
3. 当前代码真实行为、自动测试结果和浏览器实测证据。
4. 旧任务回复、历史假设和行业常见做法只能作为调查线索，不能作为通过依据。

若历史对话与当前文档冲突，以当前文档为准。若用户新确认的目标改变了现有文档，Z 必须先更新权威文档，再让程序员按文档实现。不得通过删改文档来规避实现，也不得把设计完成等同于代码完成。

## 4. 每次任务的第一性原则检查

在 A/B/C/D 开始执行前，Z 必须让执行者先确认：

1. 本次用户目标和明确不做的范围。
2. 对应权威文档及具体条款。
3. 当前代码或浏览器真实行为的基线证据。

## 6. 当前权威设计结论

### 6.1 对局收益

- 完整通关按文档结算完整收益，并且只有完整通关可以带出紫色及以上对局装备。
- 战斗失败只保留广义经济收益的 30%，包括天赋点、金币和自动分解材料；失败不能带出紫色及以上装备。
- 主动退出或主动放弃为零收益：不获得天赋点、金币、材料、装备或进度。
- 天赋点必须使用低层递减、单局软上限、早期层不独立结算、失败 30% 和主动退出 0 等防刷规则，不能让普通难度首轮未通关就打穿 84 点局外天赋。

### 6.2 Godot 与网页资产管线

- Godot 是场景和资产参数编辑入口，不是网页运行时受保护目录的直接写入器。
- Godot 只导出到 staging；之后必须经过导入器、资产管理 UI、用户确认、后端保存/应用，最终再生成项目清单和运行时覆盖。
- 禁止工具或脚本直接写入 `public/assets`、受保护的 `runtime-asset-overrides.json` 和 `dist`。
- Godot 中可见或可播放不代表网页已应用；网页必须以实际运行时配置、浏览器行为和资产引用为证据。

### 6.3 本地战斗测试

- 首页「战斗」入口仅本地开发环境展示。
- 战斗测试使用第一关地图、障碍物和正式战斗创建/生成管线，只增加本地怪物选择控制面板。
- 怪物 AI、技能、数值、阶段、资产解析和碰撞必须与真实关卡一致，禁止测试专用替代逻辑。
- 本地战斗测试是快速验收入口，不是绕过正式关卡逻辑的模拟器。
