## 1. 目标

首页首次加载、从战斗返回首页，以及每次进入战斗时，都使用同一套全屏资源加载过场承接场景切换。过场不是固定时长的假加载：它必须同时承担真实资源就绪门控，只有目标场景所需资源全部可用且最低动画时长完成后才结束。

## 3. 过场层级与动画时间轴

过场是位于首页、Canvas、战斗 HUD、弹窗和输入层之上的全视口顶层 UI。其显示期间，底层不得接收鼠标、键盘、触摸或游戏输入。

### 3.1 标准加载时间轴

适用于至少一个目标资源需要实际加载、下载、解码或重试的情况：

| 时间 | 表现 |
| --- | --- |
| `0.0–0.4s` | 从第0帧直接完整显示图1；不得显示白底 |
| `0.4–1.6s` | 图2在图1上方渐显，时长 `1.2s` |
| `1.6–4.0s` | 图1与图2保持完整可见，继续等待图3阶段 |
| `2.0–4.2s` | 图3与图1阶段重叠渐显并最终覆盖前两层，时长 `2.2s` |
| `4.2s` 之后 | 若资源或展示进度尚未完成，保持图3并继续平滑推进进度 |

标准过场最低总时长为 `4.2s` 有效前台可绘制时长。

### 3.2 全缓存时间轴

当本次清单中的全部资源在过场开始时均已缓存并可直接就绪时，仍需完整展示三阶段动画，不允许跳过；使用等比例压缩后的最低 `2.2s` 有效前台可绘制时间轴：

| 时间 | 表现 |
| --- | --- |
| `0.0–0.2s` | 从第0帧直接完整显示图1；不得显示白底 |
| `0.2–0.8s` | 图2在图1上方渐显 |
| `0.8–2.1s` | 图1与图2保持完整可见 |
| `1.05–2.2s` | 图3重叠渐显并成为最终画面 |

若只要一个必需资源不能在开始时直接就绪，就不得误用 `2.2s` 缓存路径，应使用标准 `4.2s` 路径。

### 3.3 结束

- 结束条件为“真实进度达到 `100%`”“展示进度平滑达到 `100%`”且“当前路径最低动画时长结束”三项同时成立。
- 条件成立后，图3、进度条和整个过场统一以 `0.4s` 淡出。
- 淡出结束后才允许首页交互，或启动战斗模拟、计时、敌人行为与玩家输入。
- 不提供点击、键盘、触摸、设置项或调试快捷键跳过过场的正式路径。
- `prefers-reduced-motion` 不得绕过加载门控或最低时长；本功能只有必要的透明度状态过渡，不增加平移、缩放、抖动或额外装饰动画。

## 4. 图片响应式规则

- 三张图均保持原始宽高比并以视口中心为锚点使用 `cover` 铺满全屏。
- 允许不同宽高比视口裁掉少量外缘；禁止非等比拉伸、留白、黑边或横向滚动。
- 图2的透明标题层与后续图层使用同一居中坐标系，切换期间不得漂移。
- 至少在 `1440×900` 与 `1920×1080` 验证完整铺满；同时遵守项目视觉标准中的其他桌面与窄屏断点。

## 5. 真实就绪与平滑展示进度条

- 进度条从图1出现的第一帧持续显示到过场淡出结束，位于视口底部安全区并水平居中。
- 使用响应式宽度；轨道为半透明深色底、暗金描边，填充色取图2标题的暗红橙色。
- 进度条中央显示平滑后的整数百分比，不增加加载提示、技巧或其他文案。
- 加载器必须分别维护“真实进度”和“展示进度”：真实进度按“已就绪必需素材数量 ÷ 本次必需素材总数量”计算；每个清单项只在满足其就绪条件后计数，真实进度单调不回退。
- 展示进度只能逐帧、单调地追赶真实进度，不得因资源批量完成而从低数值突然跳到高数值或 `100%`；展示进度任何时刻不得超过真实进度。
- 当前动画最低时长尚未结束时，展示进度还必须受当前时间轴完成比例约束。即使真实进度在开始时已经是 `100%`，展示进度也要从 `0%` 开始，沿当前 `2.2s` 或 `4.2s` 最低时间轴平滑增长；允许为了满足可见增量上限而在最低动画时长结束后继续增长，禁止为了准点结束而跳到 `100%`。
- 若最低动画时长结束时真实进度仍低于 `100%`，保持图3并让展示进度平滑追赶真实进度；后续真实进度跳升时仍不得直接跳数。真实进度未达到 `100%` 时，展示进度不得显示 `100%`。
- `2.2s`／`4.2s` 均按“有效前台可绘制时长”计算：`document.hidden` 期间不累计；主线程长任务或低帧造成相邻回调间隔超过 `100ms` 时，本次最多只累计 `100ms`，超出部分不得在恢复后补算。
- 平滑推进必须使用有效经过时间插值或等价实现，不得按固定帧数累加。后台切页、低帧率和不同刷新率下，恢复后必须从暂停前的展示值继续，不得按墙钟追赶、跳数或直接补到 `100%`。
- 可见进度以 `100ms` 为验收采样窗口时，任意相邻样本增量不得超过 `5` 个百分点；正常刷新率下应更连续。该上限同样适用于资源批量完成、页面恢复和主线程长任务恢复后的首个可绘制更新。
- 图片、图标、精灵图和动画帧：完成下载并可解码／绘制后就绪。
- 字体：完成字体加载并可供目标 UI 使用后就绪。
- BGM 与音效：完成下载并达到可用状态后就绪；不要求在过场内播放，正式播放继续服从浏览器用户交互授权。
- 配置数据：完成下载、解析和最低结构校验后就绪。
- 缓存全部命中时，真实进度可以立即达到 `100%`，但展示进度必须在不少于 `2.2s` 的全缓存动画内从 `0%` 平滑增长到 `100%`；允许实际增长时间超过 `2.2s`，不得先显示 `100%` 再空等动画结束。
- 平滑展示只改变玩家看到的数值与填充宽度，不得反向修改真实就绪状态，也不得让未就绪资源提前通过加载门控。

## 6. 首页资源清单

首页加载清单按功能边界定义，覆盖以下首页内容直接依赖的图片、图标、动画、字体、音频和配置：

- 猎手之家；
- 铁匠铺；
- 告示牌；
- 传送门；
- 角色选择；
- 物品仓库；
- 设置；
- “开始游戏”及其内部页面、弹窗与展示内容；
- 角色选择所需头像、立绘和预览动画；
- 三张正式过场素材。

首页清单不得包含所有关卡的地图、所有关卡怪物或未进入战斗就不需要的战斗动作素材。首页内部打开或切换上述模块时不再重复播放过场，因为其资源已由首页门控统一保证。

## 7. 战斗资源清单

战斗清单必须由玩家本次选择的目标关卡、当前角色和当前运行模式动态生成，至少包含：

- 当前所选关卡／战役的地图、地面、障碍、装饰与环境表现；
- 当前关卡合法出现的普通怪、精英、Boss 及其完整动作素材；
- 当前关卡怪物使用的技能特效和音效；
- 全部战斗 UI 与其字体、图标和音效；
- 当前选中角色在战斗中的移动、攻击、受击、死亡等完整动作；
- 全部玩家技能使用特效；
- 当前战斗所需配置数据；
- 三张正式过场素材。

不得因为进入一个关卡而一次加载其他关卡的地图和怪物。已在首页或此前战斗中就绪且版本未变化的公共素材必须复用缓存，但仍计入本次清单的“已就绪”统计。

## 8. 触发规则

- 首次打开或刷新游戏：播放首页加载过场。
- 从战斗结算、退出或其他正式返回路径进入首页：重新校验首页清单并播放；通常走全缓存 `2.2s` 路径。
- 首页内部模块切换：不播放。
- 每次确认进入正式战斗：按本次目标关卡动态生成清单并播放。
- 本地战斗／关卡测试入口若进入正式战斗渲染与模拟，也必须消费同一加载门控，不能绕过资源就绪规则；其生产隐藏和存档隔离规则保持不变。

## 9. 加载失败与重试

- 任一必需项失败时，不结束过场、不启动目标场景，也不允许缺失素材回退进入。
- 只重试失败项；已就绪项保持缓存和进度，不重复下载。
- 重试退避固定为首次等待 `1s`，之后依次等待 `2s`、`3s`、`5s`，后续固定每 `5s` 重试一次。
- 自动重试没有次数上限，直至所有必需项成功。
- 失败项不计入已就绪数量，进度条停留在真实百分比；不得用假 `100%`、静默 fallback 或跳过按钮规避失败。
- 重试等待期间页面与进度动画保持响应，不能阻塞主线程。

## 10. 架构与状态边界

- 使用稳定的资源 manifest key，按首页 UI、角色、关卡环境、怪物、战斗 UI、技能 FX、音频、字体和配置分域；禁止在组件中临时遍历 DOM 或依赖文件名猜测“全部素材”。
- 资源加载器负责清单、去重、缓存、就绪状态、重试和进度；过场 UI 只消费只读加载快照，不自行判断战斗素材。
- 首页与战斗状态机消费统一的加载门控。战斗模拟仍由战斗内核拥有；过场 UI 不直接修改敌人、计时、技能或输入状态。
- 场景启动门控与页面淡出必须是单向、幂等状态迁移，避免重复点击、React 重渲染或 Strict Mode 导致重复开局、重复生成怪物或重复播放结束回调。
- 资源版本变化后旧缓存不得冒充已就绪；相同 manifest key 与版本只加载一次。

## 11. 不变边界

本功能不得改变：

- 首页各模块的功能、数据和入口；
- 角色、装备、技能、天赋、套装及其数值和规则；
- 关卡怪物池、生成数量、AI、碰撞和伤害；
- 战斗奖励、掉落、结算和存档；
- 正式战斗与本地测试的既有隔离；
- 当前地图、遮罩、HUD 与特效的相对战斗层级。

## 13. 最低验收标准

### 13.1 动画与视觉

- 冷加载按 `0.4 / 1.2 / 2.4 / 2.2s` 的重叠时间轴运行，最低 `4.2s` 有效前台可绘制时长；全缓存路径完整播放最低 `2.2s` 有效前台可绘制时长。后台或主线程长阻塞会延长实际墙钟覆盖时长。
- 图1从第0帧直接显示，图2随后在图1上方渐显，图3最后覆盖；不得出现白底，也不得出现错误层序、闪白、闪黑、破图或旧页面残影。
- `1440×900`、`1920×1080` 均全屏铺满、中心稳定、无拉伸、黑边、白边、裁切关键标题或横向滚动。
- 满足退出条件后统一淡出 `0.4s`。

### 13.2 资源与进度

- 首页清单覆盖八类首页功能及其全部直接依赖，不请求其他关卡地图和怪物。
- 战斗清单只请求本次关卡地图／怪物、当前角色动作及公共战斗依赖，不请求其他关卡地图和怪物。
- 实际请求只使用项目内资源，不出现 `/Users/.../Downloads` 运行时路径。
- 真实就绪数与真实进度一致；展示进度不超过真实进度。冷加载、部分缓存、全缓存、单项失败后恢复均不回退、不提前到 `100%`，且批量完成时无突然猛增。
- 全缓存路径的展示进度用不少于 `2.2s` 从 `0%` 平滑到 `100%`；标准路径用不少于 `4.2s` 平滑推进。为满足相邻可见采样增量上限，两条路径均允许超过最低时长；若资源更慢，则保持最终画面并继续平滑追赶，直到真实进度与展示进度均为 `100%`。
- 后台与主线程长阻塞不计入有效时间；恢复后的可见进度继续平滑，`100ms` 相邻样本增量不超过 `5` 个百分点。
- 失败项按 `1/2/3/5/5...s` 无限重试，已成功项不重复加载。

### 13.3 状态与回归

- 过场显示及 `0.4s` 淡出期间，首页不可交互；战斗计时、敌人 AI／生成、玩家移动／攻击和技能输入均未开始。
- 淡出完成只启动一次目标场景，不重复创建战斗或敌人。
- 首页内部模块切换无重复过场；每次进入战斗以及返回首页按规则播放。
- 战斗规则、UI 内容、奖励、存档和本地测试隔离均无回归。

### 13.4 证据要求

- 自动化至少覆盖清单去重、真实进度、平滑展示进度、缓存／冷加载有效时间轴、批量资源完成无跳变、后台暂停、主线程长回调间隔截断、失败退避、无限重试、状态幂等和战斗门控。
- 类型检查、生产构建和 `git diff --check` 通过。
- C／D 必须使用本轮新浏览器会话分别提供冷加载、缓存返回、首页→战斗、战斗→首页、失败重试和两个目标桌面分辨率的截图／DOM／网络／console 证据；自动化不能替代真实浏览器验收。
